## 主要判断

最大的结构问题是校验与合并没有集中在真正的边界：热路径反复清洗已经规范化的配置，多个写入入口各自承担一部分并发处理，测试替身缺少的平台接口又催生了生产降级逻辑。

测试的突出问题集中在字体切换扩展。`performance.test.cjs` 与 `regression.test.cjs` 合计约 18.3 万个字符，既包含必要的行为验证，也包含重叠场景和精确锁定内部调用次数的断言。推荐按行为契约重组，并删除重复的负载与实现细节断言。

本轮还复现了并发保存覆盖、规则静默截断、字体选择器误判，以及同一面板的双重动画。现有测试全部通过与这些问题同时存在，下一步应替换重复覆盖，把检查移到真实缺口上。

## 1. P1：三个仓库的保存入口存在并发覆盖

自动间距的位置是 `ui.js:83—84`、`ui.js:107—110`。中西文字体替换的位置是 `options.js:200—202`、`popup.js:73—85`、`popup.js:103—109`。两者都先读取、合并，再写回整个 `settings` 对象；页面自己的 `saving`/`busy` 只约束该页面。

在独立 Chromium 中打开两个实际设置页面，使用共享的存储替身，让两个保存操作都读取同一份旧快照，再放行写入。自动间距中，窗口 A 关闭全局，窗口 B 添加站点规则，最终存储为 `enabled: true` 且保留新规则；中西文字体替换中，窗口 A 关闭全局，窗口 B 把中文字体改为 `Courier New`，最终同样为 `enabled: true`。窗口 A 的修改被覆盖了。

字体切换已经在 `shared.js:330—340` 使用原生写入锁，但 `popup.js:21` 的全局开关直接调用 `storage.sync.set()`。设置页在 `shared.js:342` 读取旧值后，弹窗关闭全局，设置页随后于 `shared.js:380` 发布包含旧开关的完整合并结果，就会把开关写回开启。本轮用实际 `writeSettings()` 与受控存储替身复现了这一交错，最终 `enabled` 为 `true`。

推荐收拢为每个扩展的一处写入入口，所有设置页、弹窗与重置操作共同参与同一套串行处理。“读取最新值—合并—发布”应处于同一个临界区；简单字段修改也走该入口。保留三方字段合并，删除各入口重复的写入编排。验证用一个可控制读写顺序的并发场景，替换部分顺序更新场景。

## 2. P2：中西文字体替换把容量防御变成了静默丢失

`shared.js:95` 对站点规则直接执行 `.slice(0, 500)`；`shared.js:72`、`shared.js:82` 对名单也进行数量和名称长度截断。设置页 `options.js:38—50` 收集表单时立即调用 `normalize()`，之后保存，界面没有与站点数量对应的拒绝或提示。

本轮向实际 `normalize()` 输入 501 条有效规则，返回 500 条。由于未保存状态也依据规范化后的 `read()` 比较，第 501 条还可能留在表单上，同时显示已保存。

推荐把本地设置的容量处理移到保存边界：完整保留表单草稿，超出明确预算时定位字段并停止保存。网页消息的输入校验与用户持久配置的保存校验应分别承担自己的职责。这里可以删除运行期反复截断用户配置的做法。

## 3. P2：中西文字体替换在每条字体声明上反复归一化配置

`shared.js:450—456` 的 `prepend()` 调用 `normalize()`，随后进入 `punctuationFaces()` 与 `chineseFamilies()`；前者又经过 `unicodeRange()`、`characters()`，这些入口继续规范化配置。每次都会重新处理字体别名、名单和站点规则。

本轮在内存中的实际源码插入计数，只增加计数语句，不改变返回值。对已经规范化、携带 1000 个字体别名的配置调用 200 次 `prepend()`，记录到 800 次 `normalize()`。这个重复成本来自调用关系，随页面字体声明数量一起增加。

推荐在配置加载或变更时生成一次工作配置，预先准备目标名称集合、字符范围、字体别名和生成字体组。内部纯函数接收这份工作配置；公开输入入口负责一次校验。无需再增加通用缓存层、缓存容量或另一套失效系统。

## 4. P2：测试替身的不完整接口进入了生产逻辑

以下几处可以直接收紧：

| 位置 | 当前分支 | 精简动作 |

| 字体切换 `shared.js:330—339` | 原生锁之外再维护 `WeakMap` Promise 队列 | 扩展页面统一使用原生锁；Node 测试提供确定性的锁适配 |
| 中西文字体替换 `options.js:221—222` | 明文为未加载套件的测试环境保留分支 | 测试加载真实 `kit/kit.js`，生产直接初始化 |

原生锁之外的队列只在同一 JavaScript 环境内串行，覆盖不了另一个扩展页面；在生产写入协议里保留两套实现，反而增加理解成本。统一入口与明确的平台依赖更干净哦。

## 5. P2：共用界面工具存在死代码，并与本地动画重复接管

三个仓库的 `kit/kit.js` 字节内容相同，共 167 行。自动间距的生产脚本没有任何 `DSH` 调用，设置页仍加载并打包整个工具文件。字体切换只调用 `initRailSpy()`；中西文字体替换调用 `initRailSpy()` 与 `initDetails()`。`debounce()`、`formatBytes()`、标签页、toast、忙碌工具等导出在当前生产调用中没有使用。

更具体的重复发生在中西文字体替换 `options.js:222—240`：先初始化套件的详情动画，紧接着又给全部 `details` 注册本地动画。“本机字体名称”使用 `font-library` 类，恰好命中两套处理。

在 Chromium 中加载这两段实际代码，单击一次该面板的 `summary`，记录到三个动画：`DETAILS` 高度、`DIV` 透明度、第二个 `DETAILS` 高度。两个高度动画由不同的展开状态变量控制，最后清理也各自执行。

推荐自动间距停止加载和打包未使用的 `kit.js`；其 CSS 保留。其余两个仓库按实际需要保留工具。详情展开统一由一处实现处理，删除中西文字体替换的第二套监听器；字体切换自身 `options.js:367—410` 的相近动画也一并收拢。对应打包测试删除对无调用脚本的强制要求。

## 6. P2：字体切换的 MIME 校验写得宽于实际契约

`background.js:75` 使用 `/^text\/css\b/i`，`text/css-invalid` 与 `text/css+json` 都能通过，因为 `/css` 后的连字符或加号构成正则单词边界。另一仓库的 `background.js:91` 已使用媒体类型后只允许空白、分号或结尾的表达式。

本轮直接核对当前表达式，`text/css-invalid` 的匹配结果为 `true`。推荐统一为精确的 CSS 媒体类型判断。现有 `tests/background.test.cjs` 的响应校验表里增加这一行即可，继续复用现有场景。

## 7. P2：生成字体链存在重复项，测试反而固定了这个输出

中西文字体替换 `shared.js:335—382` 会把同一声明中的多个命中项分别替换为同一组目标字体。`tests/shared.test.cjs:48` 明确要求 `Arial, Microsoft YaHei, sans-serif` 的结果包含两组相同的 `SF Pro Text`、`PingFang UI SC`、`PingFang SC`。

重复的生成字体组增加 CSS 字符串长度、后续解析与快照比较成本，相同的字体组再次出现也没有增加缺字后备能力。这里推荐对扩展自己生成的重复项去重，保留原网站字体的相对顺序。

对应断言应检查目标组、原列表相对顺序、前置优先级和实际绘制结果，删掉要求重复字符串原样出现的预期。精确序列化格式只在恢复快照、参数转换等确实依赖格式的位置验证。

## 8. P2：存在只由测试维持的生产接口

中西文字体替换 `shared.js:170—172` 的 `fontCSS()` 在生产中没有调用，生产注册字体使用 `fontFaces()` 与 `FontFace`。当前调用全部来自 `tests/shared.test.cjs:17—18`、`tests/shared.test.cjs:133`。

`shared.js:450` 的 `serifDependent` 参数没有读取；引擎为它传入固定占位参数，测试也传入 `true`，实际行为完全不使用这个值。`shared.js:453` 的无 `options` 路径也只由测试调用，生产调用均提供配置。

推荐删除 `fontCSS()`、无配置的历史捷径以及未使用参数，相关测试分别转向正在使用的 `fontFaces()`、`localFontSources()` 和正常配置入口。主世界 `engine.js:847` 接收 `postMessage` 配置的旧路径也应清除：仓库当前的配置发布者 `bridge.js:23` 只发送字符串 `CustomEvent`。

另一个可随手清理的字段是设置页 `fontNameIndex.signature`：`options.js:157—161` 计算全部字体的名称签名，`options.js:215` 仅检查它的类型，未用它比较或使缓存失效。删除这份无实际判断用途的签名，缓存只保存需要消费的数据。

## 9. P2：字体选择器的防重复检查拒绝了不同字体

字体切换 `options.js:1173` 使用 `current.toLowerCase().includes(name.toLowerCase())` 检测重复字体。已有 `Arial Unicode MS` 时，选择 `Arial` 会被直接返回。

本轮加载实际设置页和字体选择器，初始内容为 `Arial Unicode MS`，点击 `Arial` 后内容仍为 `Arial Unicode MS`。这是一条过宽的防重复判断。

推荐解析字体列表并比较完整家族名；若为了选择器再维护一套解析器成本过高，直接删除这条提前返回，允许用户自行调整重复项。子字符串检查应移除。

## 11. P2：自动间距存在明确重复和低价值检查

`tests/background.test.cjs:178—198` 与 `tests/extension.test.cjs:27—43` 重复测试同一份共享配置、域名、端口、继承与顺序。推荐保留前者，把后者独有的 IDN 等输入补入同一张表，删除后者整段。纯函数测试也应移出带浏览器 `before()` 的文件，减少不相关的启动成本。

`tests/background.test.cjs:47—56` 的 `onlyKnownAPI()` 用 Proxy 把测试替身变成额外 API 白名单，后续合理使用新接口也会先被夹具拒绝。删除这一层，保留各用例真正关心的消息与样式注入断言。

`tests/background.test.cjs:221—222` 专门给 `validateRegistration()` 传坏对象，再断言这个测试辅助函数会抛错。这两行可以直接删；生产注册结果仍由现有参数断言和真实 MV3 加载验证。

`tests/early.test.cjs:208—230` 收集离散过渡诊断，却只断言注入成功与网站的 `transitionBehavior` 字符串。当前浏览器中该用例记录的实际间距为 `no-autospace`，仍然通过。推荐把它移为按需运行的浏览器行为诊断，退出默认回归入口。

提前注册与后续 USER 样式的两层实现继续保留：本轮实测普通/分层重要样式在首帧生效；行内重要样式由后续 USER 注入覆盖。后台重启后的注入顺序检查也继续保留，它覆盖独立的生命周期行为。

## 12. P2：测试与完整发布打包耦合过紧

中西文字体替换 `package.json:7` 把完整 `build-release.ps1` 放入 `pretest`。普通测试因此同时生成运行入口、压缩 ZIP、计算哈希，并覆盖下载目录里的版本包。真正的测试前置只需要准备 `main-runtime.js`。

另外两个仓库的 `tests/package.test.cjs` 也通过默认测试入口执行完整构建和复制。ZIP 根目录、文件头与内容一致性验证有实际交付价值，推荐放入单独的发布检查命令。

推荐保留三个独立入口：常规测试、性能测量、发布包检查。运行入口生成从发布打包中抽出，供常规测试使用；打包与下载目录复制继续留在发布构建中。中西文字体替换 `tests/package.test.cjs:39` 固定 `names.length === 23` 的断言同时删除，使用必需资产与排除项验证。

## 13. P3：收窄异常捕获，清理静态页面中的空值分支

中西文字体替换 `engine.js:855—857` 的 `try` 同时包住 JSON 解析与完整 `configure()`；内部实现错误会被当作无效消息一起吞掉。`engine.js:599—601` 同样把 CSSOM 可读性与整段改写放在同一个捕获区域。推荐只在消息解析、跨域读取等外部边界捕获预期失败，让内部错误保持可见。

`bridge.js:39`、`bridge.js:51` 也静默丢弃了根样式提交和配置读取错误。现有结果对象已经传回错误信息，推荐消费这些信息，给出一次明确诊断；现有队列负责串行即可，无需叠加重试系统。

字体切换设置页的 `updateGlobalStatusBadge()`、`updateEmptyRulesState()`、`checkDirty()` 等函数对固定模板节点反复判空，但同一脚本的其他初始化又直接使用这些节点。推荐在初始化统一取得必需节点，删除使用位置的重复判空；菜单关闭、未加载配置等真实可变状态判断继续保留。

## 应继续保留的机制

配置代次与任务取消、CSSOM 实际序列化快照、声明优先级恢复、原生参数转换、注册属性继承与类型语义、跨域 CSS 编码和请求预算、存储分块原子发布，都对应明确的浏览器行为或持久化契约。这里推荐压缩重复实现与重复测试，保留这些职责本身。

例如 `tests/cssom-conversion.test.cjs` 用原生 API 与扩展拦截后的 API 做对照，覆盖转换次数、异常和接收者行为；它能直接约束主世界拦截的透明性。`lifecycle.test.cjs:228—230` 对空值/数字属性名的重复循环可以移除，保留该用例后半段真正写入字体并观察结果的部分。
